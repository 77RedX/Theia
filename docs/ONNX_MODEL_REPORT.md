# Runtime Compatibility

- **onnxruntime execution**: `onnxruntime` can execute this directly. The opset version 17 generated by PyTorch is standard and fully supported by modern `onnxruntime` distributions.
- **dynamic input sizes**: **NOT supported** for spatial dimensions. While the *output* tensor has dynamic spatial axes identified by placeholder names, the *input* tensor strictly enforces `256` (height) and `448` (width). 
- **fixed resolution**: **Required**. If `onnxruntime` is fed a frame of any size other than 256x448, it will throw a shape mismatch error because the graph input definition expects exact dimensions. The batch size, however, is flexible.

# Potential Integration Issues

- **Fixed Input Size**: The most critical issue. Videos processed by the `ProcessingPipeline` retain their native resolution (e.g., 1080p, 720p). Feeding these directly into this ONNX model will cause a runtime crash.
- **Preprocessing Assumptions**: The model expects a single concatenated tensor of shape `(B, 6, H, W)` in `float32`. The `ProcessingPipeline` currently yields two separate OpenCV `uint8` BGR frames of shape `(H, W, 3)`.
- **Inconsistent Dynamic Axes**: The export process failed to mark the input spatial dimensions as dynamic, despite the output supporting them. This locks the model into 256x448.

---

# Deployment Recommendation

Based on the contracts of the `InferenceEngine` interface and the limitations of this specific ONNX graph, here are the recommendations:

- **Preprocessing ownership**: `ONNXInferenceEngine` must fully own preprocessing. It must take the two raw `uint8` BGR frames, convert them to RGB, normalize to float32, transpose from HWC to CHW, and concatenate them along the channel axis.
- **Resizing ownership**: `ONNXInferenceEngine` must own resizing. Because the ONNX graph demands exactly `256x448`, the engine must downscale (or upscale) the incoming OpenCV frames to `448x256` (WxH) *before* preprocessing. After inference, it must resize the output frame back to the original video resolution so the `ProcessingPipeline` and `VideoWriter` remain decoupled from model quirks.
- **Postprocessing ownership**: `ONNXInferenceEngine` must own extracting `middle_frame`, stripping the batch dimension, transposing CHW to HWC, denormalizing back to `[0, 255] uint8`, and converting RGB to BGR before returning the result.
